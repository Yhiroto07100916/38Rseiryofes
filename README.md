# 38Rseiryofes

日比谷高校38Rの星陵祭準備を管理するためのWebアプリケーション。

「38R版Notion」をベースに、星陵祭の準備・運営に必要な機能を追加した、
38R専用の統合管理システムを目指す。

---

## 1. プロジェクトの目的

38Rでは、星陵祭に向けて約1年間にわたって準備を行う。

メンバー間の連絡、タスク管理、予定、脚本、備品、会計、資料など、
準備に必要な情報が複数のサービスに分散すると、情報の検索や管理が難しくなる。

そこで、38Rの活動に必要な情報を一つのWebアプリケーションに集約する。

Discordなどの外部サービスはリアルタイムな連絡・通知に利用し、
本システムを「正式な情報を管理する場所」として扱う。

---

## 2. 想定ユーザー

主な利用者は38Rの生徒。

約40人程度のクラスでの利用を想定する。

また、以下のような役割を想定する。

- クラス全体
- 星陵祭実行委員
- 各担当・チーム
- チームリーダー
- 一般メンバー

1人の生徒が複数のチーム・役割に所属することを想定する。

---

## 3. 主な機能

### 3.1 メンバー管理

38Rのメンバーを管理する。

- 名前
- ニックネーム
- プロフィール
- 所属チーム
- 役割
- 連絡先等の必要な情報

1人のユーザーが複数のチーム・役割を持てるようにする。

---

### 3.2 タスク管理

星陵祭準備で発生するタスクを管理する。

- タイトル
- 詳細
- 担当者
- 複数担当
- 期限
- ステータス
- 優先度
- 作成者
- 作成日時
- 更新日時

1つのタスクを複数人で担当できるようにする。

---

### 3.3 スケジュール・カレンダー

クラス活動に関する予定を管理する。

- 全体予定
- チーム予定
- 練習
- 会議
- 締切
- 星陵祭関連イベント

カレンダー表示だけでなく、一覧・テーブル形式での表示も想定する。

---

### 3.4 お知らせ

38R内で共有する重要な情報を管理する。

- タイトル
- 本文
- 作成者
- 投稿日時
- 公開範囲
- 重要度

重要なお知らせをトップページ等に表示できるようにする。

---

### 3.5 マイページ

各ユーザーが自分に関係する情報を確認できる。

- 自分のタスク
- 自分の予定
- 所属チーム
- 自分へのお知らせ
- 自分が担当している作業

---

### 3.6 脚本・劇管理

38Rのクラス劇に関する情報を管理する。

- 脚本
- シーン
- セリフ
- 登場人物
- 配役
- 演出メモ
- 改訂履歴

Web上で脚本を編集できるエディタを用意し、
最終的にはA4縦・横のPDFとして出力できるようにする。

---

### 3.7 備品・小道具管理

劇や星陵祭準備で使用する物品を管理する。

- 備品名
- 個数
- 所有者
- 保管場所
- 使用予定
- 貸出状況
- 購入状況

---

### 3.8 会計管理

38Rの活動に関する収支を管理する。

- 収入
- 支出
- 金額
- 日付
- 項目
- 担当者
- 領収書・資料

収支状況を確認できるようにする。

---

### 3.9 ファイル・資料管理

星陵祭準備に必要な資料を管理する。

- PDF
- 画像
- 文書
- 各種資料

資料をカテゴリや関連するタスク・イベント等と紐付ける。

大量のファイルそのものはD1ではなく、
必要に応じてCloudflare R2等のオブジェクトストレージを利用する。

---

### 3.10 出欠・参加管理

練習・会議・イベント等への参加状況を管理する。

- 出席
- 欠席
- 遅刻
- 未回答

---

### 3.11 投票

クラス内での意思決定に利用する。

- 投票作成
- 選択肢
- 回答期限
- 回答状況
- 結果表示

---

### 3.12 写真・活動記録

星陵祭準備の活動記録を残す。

- 写真
- 日付
- イベント
- コメント
- 撮影者

準備期間から星陵祭当日までの記録を残せるようにする。

---

### 3.13 Discord連携

Discordはリアルタイムなコミュニケーションに利用する。

本システムとDiscordを連携し、

- タスク通知
- 締切通知
- お知らせ通知
- イベント通知

などをDiscordへ送信できるようにする。

ただし、正式な情報・状態は本システム側を正とする。

---

### 3.14 意思決定記録

クラス内で決定した内容を記録する。

- 決定事項
- 決定日
- 関係者
- 関連する投票
- 備考

後から「なぜこの決定になったのか」を確認できるようにする。

---

## 開発環境のセットアップ

### 必要な環境

- Git
- Node.js 22.16.0 以上
- npm

### 初回セットアップ

リポジトリを取得していない場合は、以下を実行します。

```bash
git clone https://github.com/Yhiroto07100916/38Rseiryofes.git
cd 38Rseiryofes
```

依存関係のインストール、ローカルデータベースのマイグレーション、開発サーバーの起動をまとめて実行します。

```bash
npm run dev:setup
```

### 2回目以降の起動

```bash
npm run dev
```

### アクセス先

- フロントエンド: http://localhost:3000/
- API: http://localhost:8787/

### 停止方法

起動中のターミナルで `Ctrl + C` を押します。

### 環境変数

必要に応じて `app/.env.example` を参考に `app/.env` を作成してください。既存のファイルは上書きしないでください。

秘密情報を含む環境変数ファイルは Git にコミットしないでください。

### ローカルデータベース

ローカル D1 のマイグレーションを手動で適用する場合は、以下を実行します。

```bash
npm run db:migrate:local
```

このコマンドはローカルデータベースを対象とします。データの削除や初期化を行う前に、必要なデータを確認してください。

### Cloudflare AI の注意

Worker の AI バインディングはリモートリソースに接続する設定です。ローカル開発中でも利用料金が発生する可能性があるため、AI 機能を使用する前に接続先と料金を確認してください。

### トラブルシューティング

- `node -v` で Node.js のバージョンを確認します。
- `npm -v` で npm のバージョンを確認します。
- 依存関係に問題がある場合は `npm run setup:deps` を実行します。
- API が起動しない場合は、Worker のログと `worker/wrangler.jsonc` を確認します。
- ポート 3000 または 8787 が使用中の場合は、該当ポートを使用しているプロセスを確認してください。

### 開発コマンド

| コマンド | 用途 |
| --- | --- |
| `npm run dev:setup` | 依存関係のインストール、ローカル DB マイグレーション、開発サーバー起動 |
| `npm run setup:deps` | 依存関係のインストール |
| `npm run dev` | フロントエンドと API を同時起動 |
| `npm run dev:app` | フロントエンドのみ起動 |
| `npm run dev:worker` | API のみ起動 |
| `npm run db:migrate:local` | ローカル D1 にマイグレーションを適用 |
