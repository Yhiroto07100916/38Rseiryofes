# PROJECT 038 — 謎解き企画・詳細設計

- 作業ブランチ: `feature/project-038-mystery`
- 対象: ログイン後の38Rseiryofes
- 企画形式: サイト内の隠し入口から始まる長編謎解き
- 問題数: 個人編12問 + 協力編3問
- 参加形式: 個人編と協力編
- エンディング: 38Rの思い出につながる温かい結末
- 状態: 企画・問題設計。実装前の仕様書

## 1. 絶対に守る設計原則

1. タスク、カレンダー、会計、台本、ファイル、備品、メンバー、出欠、お知らせ等の既存業務データを謎解きに流用しない。
2. 既存業務テーブルに謎解き用レコードやカラムを追加しない。
3. 既存業務データの表示・保存・更新・削除・権限判定に副作用を発生させない。
4. 謎解きの問題、回答、進捗、ヒント、解放状態は専用ページ・専用API・専用テーブル・専用アセットに閉じ込める。
5. 共通UIに置くのは入口を発見するための装飾・演出だけとし、既存機能のデータを読み取らない。
6. 実在の個人情報、会計情報、非公開ファイル、実際のタスクや予定を問題・答え・ヒントに使わない。
7. ストーリー中の人物・記録はフィクションとする。エンディングに実際の写真や思い出を掲載する場合は、掲載許可を得た素材だけを別途キュレーションする。
8. スマートフォンだけで全問題を解けるようにする。キーボード操作、開発者ツール、外部サイト、特定端末を必須にしない。
9. ヒントを使ってもクリア資格や基本報酬に不利益を与えない。
10. 個人編をクリアしなくても通常のサイト機能はすべて利用できる。

## 2. 企画概要

### タイトル

**PROJECT 038 — 余白に残された手紙**

### キャッチコピー

「なくなった記録を探していた。最後に見つかったのは、誰かに伝えたかった言葉だった。」

### ジャンル

- ミステリー: 出所不明の記録、欠けたページ、謎の記録係
- 暗号・パズル: 文字抽出、座標、並べ替え、論理、モールス、シーザー暗号
- 探索: 共通UIの隠し入口と専用ページ内の記録室
- 軽いユーモア: 一部の記録に、少し肩の力が抜けるメモを入れる
- 感動: 最後に、記録は誰か一人のものではなく、関わった人たちの小さな記憶でできていたと分かる

### ストーリー

ログイン後のサイトを使っていると、共通フッターの片隅にある小さな記号が、ある操作をきっかけに反応する。

表示されたのは「記録番号 038」。通常の一覧には存在しない記録だという。

入口を見つけた人は、架空の保管システム「MARGIN」に接続する。そこには、かつて誰かが残した12個の問題記録と、答えを組み合わせるための5枚の記録片、そして封印された協力者向けの記録がある。

記録係は、最初は正体を明かさない。探索が進むにつれ、記録片は単なる暗号ではなく、誰かが準備期間の中で残した「小さな出来事」を表していると分かっていく。

最後の手紙には、記録係が特定の一人ではなく、何かを一緒に作った人たち全員に向けて記録を残していたことが書かれている。

この物語はフィクションであり、実際に存在した秘密の人物・事件・データがあるかのようには表現しない。

## 4. PHASE 0 — 隠し入口

### 配置

共通フッターの装飾記号として、小さな「✧」を置く。通常のリンクや業務機能の一部にはしない。

### 発見方法

1. 共通フッターの装飾記号「✧」を3回タップすると、短い信号演出が表示される。
2. 演出には次の文章を表示する。

   > いつも画面の一番上にいて、どのページからも帰れる場所。
   > そこにある星を、3回たたけ。

3. ユーザーは共通ヘッダーのサイトロゴにある小さな星印を3回タップする。
4. 正しい操作でロゴが一瞬だけ変化し、「記録番号 038 / MARGINへ接続」というボタンが現れる。
5. ボタンを押すと専用ルート `/mystery` を開く。

入口の操作は共通UIの装飾状態だけで判定する。タスク・予定・ファイル等のデータやAPIは参照しない。

### UX・アクセシビリティ

- タップ回数だけに依存せず、キーボードのEnter/Spaceでも操作できる。
- タップ対象は十分な大きさを確保する。
- 入口の演出は一度閉じても再表示できる。
- 入口を見つけられない人向けに、通常サイトの利用を妨げない範囲でヒント導線を用意する。管理者によるイベント告知やヒント公開で補助できる。
- 入口発見は個人の進捗として保存する。

## 5. 個人編 — 全12問（上級者向け改訂版）

### 難易度方針

「日比谷高校の生徒が、知識だけでは即答できず、紙に書いて整理したり、複数の問題の答えを持ち寄ったりして悩む」水準を目標とする。

- 1問につき、最低2段階の推論を必要とする。
- 公式・暗号方式・記号の読み方など、問題を解くために必要なルールは問題画面内に提示する。学校で習っていない専門知識を知っていることは前提にしない。
- ただし、提示されたルールをどう使うか、どの情報を組み合わせるかは自力で考える必要がある。
- 個々の問題は独立して解けるものと、前問の答えを鍵として使うものを混在させる。
- 早押しや総当たりではなく、推理の筋道が正しいことを重視する。
- 目安時間は個人編全体で2〜4時間。問題ごとの想定時間は5〜25分。テストプレイで調整する。
- 以下の暗号はすべて問題内に必要な規則・表を提示する。外部検索や開発者ツールは不要。

### 問題1「鍵のない暗号」

- 種類: アフィン暗号・合同式
- 表示する暗号文: `QIPMWV`
- 問題文: 「A=0, B=1, …, Z=25とする。記録係は各文字を `E(x) ≡ 5x + 8 (mod 26)` で暗号化した。元の文字列を復号せよ。」
- 正解: **MARGIN**
- 解法: 5の逆元は26を法として21（5×21≡1 mod26）。したがって `x ≡ 21(y−8) (mod 26)` で各文字を戻す。
- 報酬カード: `No.4 / L`
- ヒント1: 「暗号化の式を、元のxについて解き直せないか。」
- ヒント2: 「5x≡y−8 (mod26)。5を掛けて1になる数を探す。」
- ヒント3: 「5×21=105≡1 (mod26)。逆変換はx≡21(y−8)。」
- 解説: 暗号文を1文字ずつ逆変換するとMARGINになる。この答えは後の問題5・9で鍵として再利用する。

### 問題2「七つの扉」

- 種類: 中国剰余定理・合同式
- 問題文: 「ある番号Nは、3で割ると2余り、5で割ると3余り、7で割ると2余る。条件を満たす最小の正整数Nを求めよ。」
- 正解: **23**
- 解法: 3と7で割った余りがともに2なので、N−2は21の倍数。N=21k+2を5で割った余りが3となる最小のkを探す。k=1でN=23。
- 報酬カード: `No.1 / T`
- ヒント1: 「余りが同じ2になる、3と7に注目。」
- ヒント2: 「Nを21k+2と置ける。」
- ヒント3: 「21k+2≡3 (mod5)、つまりk≡1 (mod5)。最小はk=1。」
- 解説: N=23は3、5、7でそれぞれ2、3、2余る。より小さい正整数で条件を満たすものはない。

### 問題3「消えた項」

- 種類: 数列・階差数列
- 表示する数列: `3, 8, 18, 35, 61, □`
- 問題文: 「この記録は、3階差分が一定になる規則で作られている。□に入る数を求めよ。」
- 正解: **98**
- 解法:
  - 1階差分: 5, 10, 17, 26
  - 2階差分: 5, 7, 9
  - 3階差分: 2, 2
  - 3階差分が一定なので次の2階差分は11、次の1階差分は37、次の項は98。
- 報酬カード: `No.6 / G`
- ヒント1: 「元の数列の隣同士を引いた列を作る。」
- ヒント2: 「差分をもう一度、さらにもう一度取る。」
- ヒント3: 「3階差分が2で一定。次の2階差分11、1階差分37。」
- 解説: 61+37=98。単に見た目の規則を当てるのではなく、問題文で指定された階差の条件を使う。

### 問題4「五つの記録の順番」

- 種類: 順序論理パズル
- 問題文: 「A〜Eの5枚の記録を古い順に並べる。各記録の時刻は異なり、次の条件をすべて満たす。」
  1. Eは最後である。
  2. CはAの直後である。
  3. BはDより前である。
  4. Dは最初でも最後でもない。
  5. AはBより前である。
- 問題: 「古い順の並びを答えよ。」
- 正解: **A-C-B-D-E**
- 解法: CがAの直後、AがBより前、BがDより前なのでA→C→B→Dの順。Eが最後という条件も満たす。Dが最後ではない条件からも矛盾しない。全条件を満たす並びは一意。
- 報酬カード: `No.2 / H`
- ヒント1: 「『直後』という条件を最初に固定する。」
- ヒント2: 「A、C、B、Dの順序関係をつなげる。」
- ヒント3: 「A→C→B→D→E。」
- 解説: 条件を有向関係として整理すると一意に決まる。

### 問題5「二重に閉じた手紙」

- 種類: ヴィジュネル暗号・前問連動
- 表示する暗号文: `YEDUZL`
- 問題文: 「この手紙は、問題1で復元した鍵を使ってヴィジュネル暗号で暗号化されている。A=0〜Z=25とし、暗号化は各位置で `C=(P+K) mod 26`。鍵を繰り返して復号せよ。」
- 使用する鍵: 問題1の答え **MARGIN**
- 正解: **MEMORY**
- 解法: `P=(C−K) mod26`。鍵MARGINを繰り返して各文字から引く。
- 報酬カード: `No.8 / T`
- ヒント1: 「問題1の答えは、単なる単語ではなく鍵として使える。」
- ヒント2: 「鍵の文字を数値にし、暗号文から引く。」
- ヒント3: 「MARGINを繰り返し、YEDUZLから各文字の値を引くとMEMORY。」
- 解説: 問題1と問題5を解いて初めて復号できる連動問題。

### 問題6「最短の帰り道」

- 種類: グラフ理論・最短経路
- 画面: 6つの地点A〜Fを辺で結んだ重み付きグラフを表示する。辺と距離は次の通り。
  - A-B: 4
  - A-C: 2
  - B-D: 5
  - C-D: 1
  - C-E: 7
  - D-E: 2
  - D-F: 8
  - E-F: 3
- 問題文: 「AからFまで、同じ地点を二度通らずに移動する。総距離が最小になる経路と、その距離を答えよ。」
- 正解: **A-C-D-E-F、距離8**
- 解法: A-C-D-E-Fの距離は2+1+2+3=8。他の経路（A-B-D-E-F、A-C-E-F、A-C-D-Fなど）と比較して最小であることを確認する。
- 報酬カード: `No.3 / E`
- ヒント1: 「最初にAから出る辺を2通りに分けて考える。」
- ヒント2: 「CからFへはDを経由する場合とEへ直接行く場合を比べる。」
- ヒント3: 「A-C-D-E-Fの合計は8。」
- 解説: 最短経路問題。画面上では経路をタップして回答する。

### 問題7「隣り合わない二人」

- 種類: 場合の数・余事象
- 問題文: 「A、B、C、D、Eの5人を一列に並べる。AとBが隣り合わない並べ方は何通りあるか。」
- 正解: **72**
- 解法: 全体は5!=120通り。AとBを一つのブロックとみなすと、ブロックと残り3人の並べ方は4!通り、ブロック内のAB/BAが2通り。隣り合う場合は2×4!=48通り。したがって120−48=72。
- 報酬カード: `No.5 / I`
- ヒント1: 「条件を満たす場合を直接数えるより、全体から引く方が楽かもしれない。」
- ヒント2: 「AとBが隣り合う場合を、ひとつの塊として数える。」
- ヒント3: 「5!−2×4!=72。」
- 解説: 余事象を使う場合の数。

### 問題8「三つの箱」

- 種類: 真偽論理
- 問題文: 「鍵はA、B、Cのいずれか一つの箱に入っている。各箱には次の札が貼られている。札の文章のうち、真であるものはちょうど一つだけ。」
  - Aの札:「鍵はBには入っていない」
  - Bの札:「鍵はBに入っている」
  - Cの札:「鍵はCには入っていない」
- 問題: 「鍵が入っている箱を答えよ。」
- 正解: **C**
- 解法:
  - Aに鍵がある場合、AとCの札が真になり2つ。
  - Bに鍵がある場合、BとCの札が真になり2つ。
  - Cに鍵がある場合、Aの札だけが真になる。
- 報酬カード: `No.7 / H`
- ヒント1: 「箱を一つずつ仮定し、札の真偽を表にする。」
- ヒント2: 「Aの場合とBの場合は、真が2つになってしまう。」
- ヒント3: 「Cに鍵がある場合だけ、真は1つ。」
- 解説: 場合分けによる真偽判定。

### 問題9「列の向こうの文章」

- 種類: 鍵付き転置式暗号・前問連動
- 表示する暗号文: `ANSXIXPOTXSX`
- 問題文: 「問題1で得た鍵MARGINを使う。暗号化時は文章を左から右へ6列に書き、末尾をXで埋めた。次に鍵の文字をアルファベット順に並べ、その順で列を上から下へ読んで暗号文を作った。元の文章を復元せよ。」
- 使用する鍵: **MARGIN**
- 正解: **PASSITON**
- 解法:
  1. MARGINのアルファベット順はA,G,I,M,N,R。元の列番号では2,4,5,1,6,3。
  2. 暗号文を3文字ずつ区切り、各列に戻す。
  3. 3行×6列の表を復元し、行方向に読む。
  4. 末尾のパディングXを除く。
- 復元される表:
  `P A S S I T`
  `O N X X X X`
- ヒント1: 「文字を置き換える暗号ではなく、並べ方を変える暗号。」
- ヒント2: 「鍵MARGINをアルファベット順に並べたときの列順を求める。」
- ヒント3: 「列順は2,4,5,1,6,3。各列3文字ずつに分けて表へ戻す。」
- 解説: 列の順番を元に戻して横読みするとPASSITON。Xは埋め草。

### 問題10「行列の封印」

- 種類: 行列暗号・mod26
- 表示する暗号文: `XGNILC`
- 問題文: 「A=0〜Z=25とする。2文字ずつ列ベクトルにし、次の行列を左から掛け、各成分を26で割った余りにすることで暗号化した。元の文章を復号せよ。」
  [
  C = egin{pmatrix}3&3\2&5end{pmatrix}P pmod{26}
  ]
- 正解: **FUTURE**
- 解法: 行列式は9。9のmod26における逆元は3。逆行列は
  [
  egin{pmatrix}15&17\20&9end{pmatrix}
  pmod{26}
  ]
  これを暗号文の2文字ずつに掛けて復号する。
- ヒント1: 「行列を逆に戻すには、逆行列が必要。」
- ヒント2: 「行列式9のmod26での逆元を求める。」
- ヒント3: 「9×3≡1 (mod26)。逆行列は提示された行列になる。」
- 解説: 逆行列を使ってXG / NI / LCを復号するとFU / TU / RE。
- 注意: 問題画面には行列式・逆元の求め方を説明する折りたたみ資料を用意してよいが、逆行列そのものは最初から表示しない。

### 問題11「八枚の記録片」

- 種類: メタ謎・情報統合
- 前提: 問題1〜8の報酬カードをすべて獲得している。
- カードは次の通り。
  - 問題1: `No.4 / L`
  - 問題2: `No.1 / T`
  - 問題3: `No.6 / G`
  - 問題4: `No.2 / H`
  - 問題5: `No.8 / T`
  - 問題6: `No.3 / E`
  - 問題7: `No.5 / I`
  - 問題8: `No.7 / H`
- 問題文: 「見つけた順番は、残された順番とは限らない。記録片に刻まれた番号を使い、正しい順に並べ直せ。」
- 正解: **THELIGHT**
- 解法: No.1〜No.8の順に文字を読む。
- ヒント1: 「問題を解いた順番は関係ない。」
- ヒント2: 「カードに共通して書かれたNo.を使う。」
- ヒント3: 「No.1から並べるとT,H,E,L,I,G,H,T。」
- 解説: 8問の成果を統合するとTHE LIGHTという語句が現れる。

### 問題12「未来へ渡すもの」

- 種類: 最終メタ謎・意味解釈
- 前提:
  - 問題9の答え: **PASSITON**
  - 問題10の答え: **FUTURE**
  - 問題11の答え: **THELIGHT**
- 最終画面に表示する文章:

  > 記録係が残した三つの断片。
  >
  > PASS IT ON
  >
  > THE LIGHT
  >
  > FUTURE
  >
  > これらを、ひとつの願いとして読み直せ。

- 正解: **PASS THE LIGHT TO THE FUTURE**（日本語回答は「未来へ灯りをつなぐ」も受理）
- 解法: PASS IT ONは「次へ受け渡す」、THE LIGHTは「灯り」、FUTUREは「未来」。三つを自然な一文に再構成する。
- ヒント1: 「三つの英語を別々の答えとして扱わず、一つのメッセージにする。」
- ヒント2: 「何を、誰に、どうするのかという文に組み立てる。」
- ヒント3: 「灯りを、未来へ、受け渡す。」
- 解説: 記録係が残したかったのは、過去の記録を閉じ込めることではなく、そこで受け取ったものを次の人へ渡していくことだった。

## 6. 個人編のエンディング

### エンディング演出

端末に「すべての記録片を復元しました」と表示した後、最後の手紙を開く。

> ここまで見つけてくれて、ありがとう。
>
> 最初は、なくなった記録を探しているのだと思っていた。
>
> でも、本当に残したかったのは、完璧な記録でも、誰か一人の功績でもない。
>
> 何気ない会話や、うまくいかなかった日や、少しずつ形になっていったもの。
>

## 7. 協力編 — 3問

協力編は個人編をクリアした人が参加できる追加章。3つの断片を別々のユーザーが解き、サーバー側で集める。

### 協力編の参加ルール

- 3つの断片枠を用意する。
- 1アカウントにつき1枠だけ提出できる。
- 同じ枠に複数人が重複提出できないようにする。
- 3つすべてが異なるユーザーから提出されたら協力編の最終画面を解放する。
- 参加者の名前や個人情報は全体画面に表示せず、提出済み枠数だけを表示する。
- 参加者が集まらなくても個人編のクリア状態・報酬は維持する。
- 協力編は必須にしない。参加者が少ない場合のテスト用・運営用リセット手段を用意する。

### 協力問題13「3つの断片」

- 種類: 3人分担型のミニ謎
- 3つの提出枠を用意し、異なるユーザーがそれぞれ1枠を担当する。
- Aの問題: `1人 + では` を読みとして表す。
  - 正解・断片: **ひとりでは**
- Bの問題: `いなえみ` を逆から読む。
  - 正解・断片: **みえない**
- Cの問題: `がるあきしけ` の文字を並べ替え、「景色」と「がある」を表す文にする。
  - 正解・断片: **けしきがある**
- 3つの断片をつなぐと「ひとりでは、みえない、けしきがある」になる。
- 各枠に3段階のヒントを用意する。
- 提出後は、全体画面に個人名を表示せず、3枠中何枠が埋まったかだけを表示する。

### 協力問題14「空白を埋める」

- 種類: 共同メタ謎
- 前提: 3人の異なるユーザーからA・B・Cの断片が提出されている。
- 画面: 3つの断片カードを並べ替えて自然な一文を完成させる。
- 正解: **ひとりでは見えない景色がある**
- 解き方: 「ひとりでは」は条件、「見えない」は状態、「景色がある」は結論となる順に並べる。
- ヒント1: 「3つの断片は1つの文になる。」
- ヒント2: 「条件、状態、結論の順に並べる。」
- ヒント3: 「A → B → C。」
- 解説: 3人が別々に解いた断片を合わせることで、一人では完成しなかった文章になる。

### 協力問題15「みんなの記録」

- 種類: 協力編最終問題
- 前提: 問題14をクリアしている。
- 問題文: 「ひとりでは見えなかった景色を、みんなで見つけたあとに残るものは何か。」
- 正解: **思い出**
- クリア演出: 3つの断片が1枚の記録カードにまとまり、協力編エンディングが表示される。
- エンディング文:

  > ひとりで見つけた答えも、誰かと分け合った答えも、どちらも大切な記録です。
  > ひとつずつは小さくても、集まれば一つの思い出になる。
  > PROJECT 038 — 共同記録、完成。

- 報酬: 協力編限定称号「記録の共作者」と、専用アーカイブの解放。

## 8. 問題・答えの品質管理

全問題は公開前に、作問者以外の複数人でテストプレイする。正解が複数成立しないこと、必要な情報が画面内に揃っていること、スマートフォンでも同じように解けることを確認する。

- 問題3の正しい座標列は `(3,5) (2,3) (3,4) (4,4) (3,4)`。5×5表でPHOTOになることを自動テストする。
- 問題1は3行の採用版のみを表示し、先頭文字が「よはく」になることをテストする。
- 問題9はC2だけが規則から外れることを確認する。
- 協力編の断片はA→B→Cで「ひとりでは見えない景色がある」と一意に組み立てられることを確認する。
- 各問題に正解・誤答例・ヒント1〜3・解説・スマホでの操作方法を持たせる。
- 答えの大文字小文字、全角半角、前後空白などの正規化ルールを問題ごとに定義する。
- 早解きや総当たりだけで突破できないよう、回答回数制限とレート制限を用意する。
- 問題の正解はフロントエンドの静的データに含めず、Workers側で検証する。

## 10. 技術設計方針

### 分離境界

- Nuxt: 謎解き専用ページ、コンポーネント、状態管理。
- Workers: 問題取得、回答検証、進捗保存、協力編の集計。
- D1: 謎解き専用テーブルのみ。
- R2: 謎解き専用画像・音声・演出素材のみ。
- 既存業務APIや業務テーブルから問題データを取得しない。

### テーブル案

| テーブル | 用途 |
|---|---|
| `mystery_projects` | 企画の有効状態・バージョン |
| `mystery_questions` | 問題文・表示設定・正解ハッシュまたは検証情報 |
| `mystery_hints` | 問題ごとのヒント |
| `mystery_user_progress` | 個人の解答・クリア状態 |
| `mystery_answer_attempts` | 回答試行の記録 |
| `mystery_coop_slots` | 協力編の提出枠 |
| `mystery_coop_contributions` | ユーザー別の断片提出 |

### API案

- `GET /api/mystery/status`
- `GET /api/mystery/questions/:id`
- `POST /api/mystery/questions/:id/answer`
- `POST /api/mystery/questions/:id/hint`
- `GET /api/mystery/progress`
- `GET /api/mystery/co-op`
- `POST /api/mystery/co-op/contributions`
- `POST /api/mystery/co-op/questions/:id/answer`

すべてログイン必須。ユーザーIDはセッションから取得し、リクエスト本文のuser_idを信用しない。回答検証・進捗更新はサーバー側で行う。二重送信を防ぐため、ユーザー・問題単位で一意制約を設ける。

### 実装時の注意

- 既存の認証・セッション方式を再利用する。
- 既存業務機能の権限・設定を変更しない。
- 謎解き用APIは独自の認可・入力検証を持つ。
- 回答の正規化は問題ごとに行い、過度な曖昧一致を避ける。
- 協力編はトランザクションまたは一意制約で重複提出を防ぐ。
- 問題の公開状態と正解データを分離する。
- 既存テーブルへのALTER、既存データのUPDATE/DELETEは行わない。
